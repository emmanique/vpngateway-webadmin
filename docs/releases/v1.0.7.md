# VPN Gateway Multi v1.0.7 — Pi-hole status on fresh install

## Changes
- First-time `start.sh` creates `PIHOLE_WEBPASSWORD=` instead of generating an undisclosed random password. Existing `deploy/.env` is never overwritten.
- Unauthenticated read-only WebAdmin Pi-hole status endpoints work with the LAN-only Pi-hole v6 deployment. API uses the valid `/api/dns/blocking` endpoint and retains `/api/stats/summary`.
- Version metadata is read from `VPNGW_RELEASE_VERSION` passed by Compose, avoiding stale 1.0.3 responses.

## Security boundary
The Pi-hole management page at port 8443 has no login in a fresh install. This is **only for a trusted private LAN**; do not forward port 8443 from a public WAN, and ensure an appropriate firewall/ACL at the network edge. The gateway's own WebAdmin security and VPN dataplane remain unchanged.

## Validation
Regression gates and installation package checks are run during GitHub Actions release publication. Fresh-install QA on 2026-11-09 at private IP 192.168.1.252 confirmed Pi-hole v6 returned HTTP 200 for `/api/info/version`, `/api/stats/summary`, `/api/dns/blocking`; DNS was enabled and statistics non-empty. Version/dns UI fixes require WebAdmin recreation.
