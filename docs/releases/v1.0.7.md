# VPN Gateway Multi v1.0.7 — Fresh-install QA corrections

Corrective release for a fresh installation of VPN Gateway Multi in a **trusted private LAN**.

- Pi-hole v6 dashboard: version, blocking state and summary statistics use valid API endpoints. Fresh installs set `PIHOLE_WEBPASSWORD=` for LAN-only administration; an existing local secret is preserved during upgrades.
- Real version discovery: WebAdmin API receives the image/release version from Compose; stale `1.0.3` literals no longer drive status.
- Onboarding: only **Overview** and **WAN/LAN** are accessible before network topology confirmation. Other menus unlock after confirmation; topology inputs and server-side Save lock thereafter.
- Persistence: existing network confirmation fingerprint remains stored in the application database; normal upgrades retain existing volumes and state.
- Documentation: public repository update commands, package provenance and passwordless LAN security caveat.

## Acceptance limits
Topology confirmation validates current interfaces and routes; it does not physically reconfigure them. Existing VPN profiles and host routing require separate functional tests. Unauthenticated Pi-hole administration on port 8443 must never be exposed to untrusted clients or the Internet.

## Distribution checks
GitHub Actions verifies Python onboarding contracts, frontend i18n/TypeScript compilation, deterministic deployment archives and SHA-256 checks, and publishes all three assets against the release commit.
