# v1.0.6-rc.3 — Persisted blocked-client management path

Candidate validation build, not yet stable.

- Reinstalls the exact MAC+IP+LAN+Docker-proxy HTTPS management exception on every blocked-policy recovery.
- Recreates management policy routing after controller restart or reboot.
- Periodically reconciles the Docker-proxy address if containers are recreated, replacing only owned nftables rules.
- Retains directional RX/TX accounting and dropped-packet statistics from RC2.
- The WebAdmin explicitly warns that a host with another default gateway can bypass blocked-policy enforcement.

Security requirement for stable deployment: route managed clients through this gateway or enforce L2/L3 access rules on the upstream router/switch. The gateway cannot block packets it never receives. Test this separately on a controlled client before promoting to stable.
